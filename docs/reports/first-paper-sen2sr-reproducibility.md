# SEN2SRLite 云端 CPU 差异核查与兼容策略

2026-09-08。结论：本次三个固定 development ROI 的哈希差异由 CPU intra-op
线程数变化复现。1 线程复现测速输出，96 线程复现历史 A 输出，各配置重复两次均一致。
这不是跨平台／全部样本逐字节保证，也不把微小差异宣称为完全无影响。

## 影响与决策

访问前向用户声明的严格核查线：像素最大差 ≤ `1e-6`、AURC 差 ≤ `1e-8`、
rho 差 ≤ `1e-6`。这些是本次诊断线，不是论文预注册的等效性检验。
1 线程相对历史输出最大绝对差 `5.960464477539062e-7`；三模型分歧的最大
R1 AURC 差 `4.931838237277886e-8`，其中两个 ROI 超过 AURC 核查线。
R9 AURC 最大差 `9.422936556036099e-9`，rho 最大差 `4.471084180668328e-8`。
因此不接受“所有差异均可忽略”的结论，也不事后放宽阈值。

96 线程下三个预测均与历史 A 逐字节一致，三模型分歧及上述指标差均为零。
主比较 K5–LR 不依赖 SEN2SRLite，历史 B/C 也未改动；受影响的是三模型评分
的数值可复现性及对应成本。按用户“云端为主”的决定，未来独立外部入口使用
`CloudSEN2SRLiteX4`，不修改冻结的 `SEN2SRLiteX4` 或旧测速脚本。

## 实现边界与成本

新适配器在加载和预测内固定 96 intra-op 线程，退出或异常恢复调用者线程数；
仅支持 CPU、要求已有认证模型资产，不触发缺失资产下载。provenance 增加策略版本、
线程数和 CPU/backend 配置，使新旧缓存身份分离。PyTorch 设置是进程全局的，
**只允许单 worker 串行使用**，不支持并发调用；interop 等记录项不是强制配置。
换硬件／库／backend 时必须重新核验三个固定样本，不能假定仅 96 线程就足够。

实际新适配器在调用者 1 线程下验证 3/3 历史哈希，并每次恢复为 1 线程。
三个完整 predict 调用耗时 1.042361、0.828625、0.793810 秒，含首次冷调用，
均值 0.888265 秒；加载另计 0.703141 秒。样本很少，不是稳定吞吐基准。
旧 0.209878 秒是 1 线程结果，不能用于新策略预算。结合既有 LDSR／bicubic
测量，48 ROI 推理部分暂估 **7.179 分钟**（混合测量投影，含冷调用均值），
仍不含完整输入、评分、缓存、加载及计费开销。无需为此重跑已完成 GPU 测速。
