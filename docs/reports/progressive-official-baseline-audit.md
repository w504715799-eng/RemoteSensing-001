# Progressive study: official baseline source audit

Audit date: 2026-09-09. Scope: primary paper and read-only source inspection, plus synthetic CPU arrays. No dataset pixels, prediction caches, cloud resources, third-party execution, dependency installation, model inference, or frozen protocol changes were used. This document is an audit, not an additional experimental result.

## Conclusion and identity

The frozen `w3` is a **paper-formula structural adaptation to RGBN and grouped CRC**, not an exact reproduction of the published experiments or official implementation. Calling it an “official NeurIPS baseline” without this qualification would be misleading. In particular, the released patch-score helpers and the paper's displayed patch-score equation are algebraically different. This is a substantive distinction, not just a window-size change.

Primary sources: [paper v3, sections 2.1–2.3 and 4](https://arxiv.org/html/2502.09664v3); [authors' repository](https://github.com/adamesalles/experiments-conformal-superres). The repository identifies the work as NeurIPS 2025. `git ls-remote … HEAD` and a shallow read-only checkout both resolved to **819086a9e21077010bdcee233373a25c8d32bdd0**. Checkout: `/tmp/conformal-official-audit-20260909`. This pins the retrieved revision, not a claim that it is the conference artifact revision. Local HEAD at audit: `8d9fb1723485a2d1c4e13e9317efb1fa4d73070c`; local line references below describe the inspected working tree.

Let `E` average ensemble members, `C` average bands, `B_k` denote box averaging, and `G` denote Gaussian smoothing. “Exact” below means the particular algebraic structure agrees, not full numerical reproducibility.

## Source integrity limitations that affect a reproduction claim

The inspected LIU4K [mask generator](https://github.com/adamesalles/experiments-conformal-superres/blob/819086a9e21077010bdcee233373a25c8d32bdd0/src/masks/generate_masks.py#L92) ends after saving the simple point-variance map. It defines a patch helper but never invokes it in that main block. The alternate processing script writes kernel 13/19/25 outputs, whereas main calibration consumes kernel 31. Its saved prediction is raw RGB while calibration's reference preprocessing uses normalized Lab. These observations establish that a checkout alone does not authenticate the precomputed artifacts used for the reported results. They do not establish that the published empirical results are wrong.

For a reproducible comparison, identify the intended score producer, prediction encoding, artifact generation revision, calibration path and mask polarity first. Do not silently repair the external code and then call the outcome an exact reproduction. A documented reference reimplementation and a literal released-helper comparator are different experimental objects.

## CPU evidence completed without data access

An inline synthetic script used only installed local PyTorch and the local scoring functions, with `PYTHONDONTWRITEBYTECODE=1`, one CPU thread, and deterministic tensors. No imported module from the downloaded repository was executed.

- On `(5,4,17,17)` float64 uniform random arrays (generator seed 7), `max_abs((GU+GT)−neighborhood_variance_score(window=3)) = 9.71445146547012e-17`.
- Five spatially constant members with intensities `0, .25, .5, .75, 1` produce local joint score `0.12500000000000006`. An independently written expression for the released per-member patch formula gives **0** at an interior pixel. This disproves general numerical equivalence even with matched window and representation.
- Two opposite-sign unit errors in a 9×9 window produce local mean-absolute-before-pooling risk `2/81 = 0.024691358024691357`, but absolute-after-pooling risk **0**. This demonstrates the risk-definition gap without data or statistical estimation.

These checks validate identities and counterexamples only. They provide no empirical baseline ranking, fidelity, coverage, or publication claim.

Additional CPU-only verification can be prespecified: constant/impulse/ramp boundary cases; population-versus-sample variance; normalization tie handling; finite-grid versus event-search counterexamples; grouped CRC with unequal ROI counts; and checking score polarity with explicit trusted/mistrusted masks. None requires GPU generation. Exact numerical cross-library agreement would additionally require a pinned approved environment and explicit defaults; it was not tested here.

## Reviewer-actionable next steps without altering the frozen study

1. Keep the existing primary family, eight methods, primary `full−w3` comparison, held-out roles, alpha, and terminal-use protocol unchanged. This audit does not admit a ninth method or replace `w3` after seeing results.
2. In the manuscript, label `w3` “RGBN adaptation of the paper's neighborhood-moment score under the common grouped CRC protocol.” State its five samples, central seed, kernel, Gaussian, normalization, R9, and group unit. Explain the paper/released-helper distinction in the baseline appendix.
3. Prespecify a **separate supplemental study** comparing (a) paper-formula adaptation and (b) a pinned released-helper adaptation on the same representation, risk, model and group protocol. Match one factor at a time; separately identify sensitivity analyses for kernel, Gaussian, clipping, threshold search and ensemble budget. Freeze implementation, selection rules, split roles and multiplicity before new outcome access. Do not use current terminal data to choose these settings.
4. A stronger external baseline requires new authenticated score computation and calibration, and potentially nine-member prediction generation, RGB/Lab-specific inference, an external model, public benchmark data or semantic annotations. Source inspection cannot supply these results. Existing five predictions cannot stand in for nine official runs; existing RGBN outputs cannot establish original SinSR/Liu4K results. Any authorized supplemental cache use must follow its own protocol; this audit accessed none.
5. If a literal original-paper reproduction is a publication requirement, resolve the released-path gaps with an authoritative artifact or documented author clarification, then register and execute that reproduction separately. Until then, report the limitation explicitly rather than upgrade an internal comparator's label.
