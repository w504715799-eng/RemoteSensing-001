## 实测结果

计时是完整适配器 `predict()` 前后同步的墙钟，不是 CUDA kernel 活跃时间。
它包含适配器 CPU 校验、RNG 隔离和输入／输出传输；外层验证及输出哈希计算不在内。

| 模型／设备 | 常规调用数 | 平均秒／次 | 范围（秒） | 冷启动预测（秒） | 模型加载（秒） |
|---|---:|---:|---:|---:|---:|
| Bicubic／CPU | 3 | 0.006185 | 0.004832–0.007081 | 不单列 | 0.000001 |
| SEN2SRLite／CPU | 3 | 0.209878 | 0.196487–0.228085 | 0.210975 | 0.438676 |
| LDSR／GPU | 15 | 1.615943 | 1.607087–1.636250 | 2.006149 | 5.074614 |

输入核验／准备为 0.294755 秒。LDSR 推理窗口的 PyTorch 峰值 allocated 为
4,133,724,672 bytes（3.849831 GiB），reserved 为 5,452,595,200 bytes（5.078125 GiB）。
这不是含驱动、其他进程和加载阶段瞬时峰值的整机显存，也不是最低显存规格保证。
只有 3 个开发 ROI，范围为观测最小／最大，不是置信区间。
入口未记录 CPU 型号或完整线程库设置；CPU 时间仅作为这次服务器会话的观测，
不能据此给不同硬件作精确 CPU 耗时保证，最终复现记录应补齐这些信息。

## 数值复核与未决差异

本地独立重算所有均值，并逐项核对 ROI／seed 次序、LR 张量哈希、模型已记录身份与
源 canonical SHA。LDSR 与 SEN2SRLite 的首个冷启动／常规重复输出各自哈希一致。

再与已发布 A 的预测哈希比对（仅读本地公开 JSON，不打开历史预测文件）：

- LDSR：15/15 相同；bicubic：3/3 相同。
- SEN2SRLite：0/3 相同。输入、权重和已记录 provenance 字段均一致，但输出字节不同。
  旧 A CLI 未显式固定 CPU 线程数，本次固定为 1；这只是一个待检验的可能因素，
  不是根因证明。没有数值差分，不能断言只是可忽略浮点误差，也不据此认定权重改变。

测速值仍是本次已声明配置的有效观测；它不能证明 SEN2SRLite 跨运行逐字节复现。
在最终外部冻结前，须专门核查其 CPU 执行设置及误差幅度，写入新协议的复现容差和
身份字段。不得修改旧 A 结果来消除差异，或拿 Spain 数据调试。
