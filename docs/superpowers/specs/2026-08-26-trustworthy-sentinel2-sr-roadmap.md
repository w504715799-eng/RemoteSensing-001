# 可信 Sentinel-2 超分辨率研究路线图

**日期：** 2026-08-26  
**状态：** 已批准方向，按阶段实施  
**目标：** 在只使用公开数据与开源模型的条件下，研究跨传感器域偏移下的 Sentinel-2 RGBN ×4 超分辨率可信度校准、幻觉检测与选择性回退。

## 1. 核心科学问题

现有超分辨率模型能够产生更锐利的 Sentinel-2 图像，但锐利细节不一定真实。本项目不把“再设计一个更大的生成网络”作为主创新，而回答以下问题：

> 能否使用经过统计校准的多光谱置信掩膜，识别真实 Sentinel-2 超分辨率中的高风险像素，并在跨地区、跨传感器条件下控制错误风险？

## 2. 固定范围

- 输入：Sentinel-2 L2A 的 B04、B03、B02、B08，即 RGBN，反射率范围 `[0, 1]`。
- 输出：RGBN ×4 超分辨率，从 10 m GSD 映射到约 2.5 m GSD。
- 数据：只使用公开数据集；训练、校准、验证和最终测试按地理区域分割。
- 首批模型：双三次插值、SEN2SRLite、LDSR-S2。模型通过统一接口接入，不修改其内部结构。
- 主方法：黑盒模型输出或随机多次推理产生不确定性分数；共形风险控制将分数转换为可信掩膜。
- 最终价值：检测并抑制幻觉，而不是单纯追求更高 PSNR。

## 3. 明确不做的内容

- 第一阶段不训练新的 Transformer、Mamba 或扩散主干。
- 第一阶段不处理 Sentinel-2 全 12 波段，也不混合 ×2 与 ×4 任务。
- 不把随机图像块划分当作独立样本；同一 ROI 的块不能跨数据分割。
- 不使用 OpenSR-Test 的 NAIP、Spain Urban、Spain Crops 样本调参。
- 不承诺某个期刊或中科院分区录用；目标是形成可复现、具备三区竞争力的研究证据。

## 4. 工程架构

采用单仓库、模块化流水线：

```text
公开数据 -> 标准化 SRPair -> 黑盒 SR 模型 -> SR 图像与不确定性分数
                                             |
                                             v
HR 校准对 -> 遥感局部风险 -> 共形阈值 -> 可信掩膜 -> 选择性回退
                                             |
                                             v
                          风险-覆盖率 + OpenSR 指标 + 下游任务
```

模块边界：

- `trustsr.data`：下载、波段选择、反射率归一化、ROI 级划分。
- `trustsr.models`：统一 `predict()` 接口，模型不得直接依赖数据集结构。
- `trustsr.risk`：局部反射率、光谱角和空间高频风险。
- `trustsr.calibration`：全局及分组共形风险控制。
- `trustsr.selection`：可信像素保留，不可信像素回退或融合。
- `trustsr.evaluation`：OpenSR、风险-覆盖率和下游指标。
- `artifacts/`：配置、清单、模型输出和结果表；大文件不提交 Git。

上游 NeurIPS 代码要求 Python `<3.12`，而 LDSR-S2 当前要求 Python `>=3.12`。本项目统一使用 Python 3.12，在保留数学定义和出处的前提下，以 NumPy/PyTorch 重新实现最小共形校准核心，不把原仓库作为运行时依赖。

### 双环境执行策略

- 本地 CPU 环境负责代码开发、单元测试、数据清单、双三次基线、指标计算和小样本冒烟。
- 云 GPU 环境负责 SEN2SR/LDSR-S2 批量推理、随机多次采样、训练或微调，以及后期完整实验。
- 研究方法和数据规模不受本地无 GPU 限制；本地测试使用小张量或测试替身验证相同接口。
- 第一次需要 GPU 前必须停止执行并向用户索取 SSH 连接信息，不预设云厂商、GPU 型号或 CUDA 版本。
- SSH 密钥、口令、主机地址和令牌不得写入 Git、配置文件、日志或实验产物；连接信息只用于用户授权的远程环境。
- 云端必须记录 GPU、驱动、CUDA、Python、PyTorch、Git 提交和数据清单哈希；推理输出以可校验的缓存产物回传本地继续分析。

## 5. 数据使用协议

| 用途 | 数据 | 使用规则 |
|---|---|---|
| 开发冒烟 | OpenSR-Test SPOT | 只验证数据和指标管线，不用于论文主结论 |
| 校准与内部验证 | SEN2NAIP | 按 ROI/地理区域切分，先用小子集再扩展 |
| 外部最终测试 | OpenSR-Test NAIP、Spain Urban、Spain Crops | 方法冻结后一次性运行 |
| 跨传感器验证 | SEN2NEON | 后期阶段加入，不参与早期阈值选择 |
| 下游验证 | GeoSR-Bench 的一个固定任务子集 | 只在可信方法通过前述门槛后加入 |

所有数据清单必须记录 `sample_id`、ROI、传感器、日期、地表组别和划分。若元数据缺失，样本不能进入正式的跨域统计实验。

## 6. 分阶段开发路线

### 阶段 0：可复现地基与零参数基线

**时间盒：** 1–2 天。  
**交付物：** 一个经过测试的 CPU 命令，能够加载少量 OpenSR-Test SPOT 数据、运行 RGBN ×4 双三次插值并输出 JSON 指标。  
**通过条件：** 单元测试全部通过；输入输出形状和数值范围正确；相同命令两次结果一致；结果 JSON 包含环境与数据版本。  
**停止条件：** 数据无法下载、波段顺序无法确认或 OpenSR 指标无法在 CPU 运行。先修基础设施，不进入模型阶段。

### 阶段 1：预训练模型复现

**时间盒：** 3–5 天。  
**交付物：** SEN2SRLite 适配器和固定 SPOT 开发清单上的缓存结果；GPU 可用时再增加 LDSR-S2 单图推理。  
**通过条件：** 模型输出为 `(4, 4H, 4W)`、反射率有限；结果可从缓存重复计算指标；至少完成双三次与 SEN2SRLite 的公平对比。  
**停止条件：** 当前环境没有可用 CUDA 时，不阻塞 SEN2SRLite；LDSR-S2 延后到有 GPU 的执行环境。

### 阶段 2：最小共形原型

**时间盒：** 5–7 天。  
**交付物：** 使用 SEN2NAIP 小规模地理分割，完成单一局部绝对误差、单一不确定性分数和全局阈值的风险-覆盖率实验。  
**通过条件：** IID 地理留出集上的经验风险不超过预设目标及有限样本余量；随着拒绝率上升，选择性风险总体下降。  
**停止条件：** 若不确定性排序明显无效，先比较 LDSR 多次采样方差、测试时增强方差和 LR 一致性残差，不添加复杂网络。

### 阶段 3：遥感专用风险函数

**时间盒：** 1–2 周。  
**交付物：** 反射率、局部光谱角、空间高频/幻觉三个风险分量及消融实验。  
**通过条件：** 至少一个遥感风险组合比普通像素 L1 更好地识别 OpenSR 幻觉区域，并保持可解释的风险保证。  
**停止条件：** 如果复合风险无稳定收益，论文保留最简单风险定义，避免堆叠指标。

### 阶段 4：跨域与分组校准

**时间盒：** 1–2 周。  
**交付物：** 全局、按传感器、按地区或地表类别的分组校准比较；报告每组样本量和覆盖失效。  
**通过条件：** 至少一种分组策略在域偏移测试上降低风险违反率，而且不会因组样本过少导致覆盖率崩溃。  
**停止条件：** 若分组样本不足，缩减为传感器级两组，不继续细分地表类型。

### 阶段 5：选择性回退与下游验证

**时间盒：** 1–2 周。  
**交付物：** 高风险像素回退到保守重建的融合方法，以及一个固定下游分割任务。  
**通过条件：** 相比未经选择的 SR，幻觉率下降；至少一个下游指标恢复或提高，同时报告被回退的像素比例。  
**停止条件：** 如果下游任务无收益，诚实报告“检测有效但不改善任务”，不反向调校最终测试集。

### 阶段 6：冻结、完整实验与论文

**时间盒：** 2–3 周。  
**交付物：** 冻结配置、三次随机种子结果、外部测试、消融、统计区间、运行成本和论文图表。  
**通过条件：** 任何论文表格均可由一个带配置哈希的命令重建；数据划分和失败实验均有记录。

## 7. 两个总检查点

### 检查点 A：阶段 1 完成后

只有在数据、缓存、模型输入输出和 OpenSR 指标全部可复现时，才开始共形方法。这个检查点只判断工程基础，不判断论文创新。

### 检查点 B：阶段 2 完成后

必须满足以下至少两项才继续完整论文路线：

1. 选择性风险随拒绝率呈清晰下降趋势；
2. 目标风险的经验违反率处于预定容差内；
3. 置信分数对高误差或幻觉像素的排序优于随机分数和 LR 残差基线。

若未满足，项目转为“跨传感器域差距的实证研究”，不继续增加风险函数和下游模块。

## 8. 结果管理与防泄漏

- `data/`、`artifacts/`、模型权重和缓存全部加入 `.gitignore`。
- 每次运行保存参数、Git 提交、Python/包版本、设备和数据清单哈希。
- 最终测试清单在阶段 2 开始前生成哈希并冻结，阶段 6 才执行。
- 论文主表不得混合 ×2 与 ×4、RGB 与 RGBN、L1C 与 L2A 的结果。
- 每个阶段单独评审；通过后才编写下一阶段的详细实施计划。
